## BAB 1: KECAKAPAN KERJA DASAR, K3, DAN BUDAYA KERJA

### 1.1 Pengertian dan Komponen Kecakapan Kerja

#### A. Definisi Mendalam
**Kecakapan kerja** (employability skills) adalah kemampuan yang memungkinkan seseorang tidak hanya mendapatkan pekerjaan, tetapi juga bertahan, berkembang, dan berkontribusi secara signifikan dalam organisasi. Konsep ini pertama kali dipopulerkan oleh Conference Board of Canada (2000) yang membagi menjadi tiga kelompok besar:
1. **Fundamental Skills** (kemampuan dasar): komunikasi, berhitung, manajemen informasi.
2. **Personal Management Skills** (kemampuan personal): sikap positif, tanggung jawab, adaptabilitas, pembelajaran berkelanjutan.
3. **Teamwork Skills** (kemampuan kerja tim): kolaborasi, presentasi, negosiasi, dan resolusi konflik.

#### B. Komponen Hard Skills vs Soft Skills
| Aspek | Hard Skills (Teknis) | Soft Skills (Non-Teknis) |
|-------|----------------------|---------------------------|
| Definisi | Keterampilan spesifik yang terukur | Keterampilan interpersonal dan karakter |
| Contoh | Coding, database, jaringan, desain UI | Komunikasi, kepemimpinan, empati |
| Pengukuran | Sertifikasi, ujian praktik | Penilaian perilaku, 360-degree feedback |
| Cara belajar | Kursus, pelatihan, praktik langsung | Pengalaman, mentoring, refleksi diri |

#### C. Kecakapan Kerja Spesifik untuk Pengembang Software & Game
1. **Technical Agility** – Kemampuan beradaptasi dengan bahasa pemrograman dan framework baru dengan cepat.
2. **Code Literacy** – Tidak hanya menulis kode, tetapi juga membaca dan memahami kode orang lain (code reading).
3. **Algorithmic Thinking** – Memecah masalah kompleks menjadi langkah-langkah logis.
4. **UX Empathy** – Memahami kebutuhan dan emosi pengguna.
5. **DevOps Mindset** – Memahami siklus hidup pengembangan hingga deployment dan maintenance.

### 1.2 K3 (Keselamatan dan Kesehatan Kerja) Secara Komprehensif

#### A. Sejarah dan Perkembangan K3
K3 modern dimulai pada era Revolusi Industri (akhir abad ke-18) ketika pekerja pabrik mengalami kecelakaan massal. Di Indonesia, UU No. 1 Tahun 1970 menjadi payung hukum pertama. Saat ini, K3 tidak hanya mencakup aspek fisik tetapi juga psikososial dan digital.

#### B. Elemen K3 di Lingkungan Kerja Digital (Cyber Safety)
1. **Ergonomi Digital**:
   - Posisi duduk: punggung tegak (90°), kaki menyentuh lantai, siku 90° saat mengetik.
   - Jarak monitor: satu lengan (50-70 cm), bagian atas monitor sejajar dengan mata.
   - Penggunaan filter blue light untuk mengurangi ketegangan mata.

2. **Kebersihan Data (Data Hygiene)**:
   - Tidak menyimpan password di sticky notes.
   - Menggunakan password manager (Bitwarden, 1Password).
   - Enkripsi file sensitif dan backup rutin.

3. **Kesehatan Mental**:
   - Kenali tanda-tanda burnout: kelelahan kronis, sinisme, produktivitas menurun.
   - Terapkan "Digital Sabbath": 1 hari dalam seminggu tanpa perangkat digital.
   - Manfaatkan Employee Assistance Program (EAP) jika tersedia.

#### C. K3 dalam Pengelolaan Server dan Data Center
- **Physical Security**: Akses terbatas dengan biometrik, CCTV, dan alarm.
- **Environmental Control**: 
  - Suhu: 18-27°C (ideal 21°C).
  - Kelembapan: 40-60% RH.
  - Pemadam kebakaran: menggunakan gas (FM200) bukan air untuk melindungi peralatan.
- **Redundansi**: UPS, generator cadangan, dan koneksi internet ganda.

#### D. Studi Kasus K3
**Kasus**: Seorang programmer mengalami nyeri pergelangan tangan (Carpal Tunnel Syndrome) setelah bekerja 10 jam/hari tanpa jeda.
**Analisis Akar Masalah**:
- Kurangnya ergonomi peralatan.
- Tidak ada kebijakan istirahat.
- Stress memperparah ketegangan otot.
**Solusi K3**:
- Ganti mouse dengan vertical mouse dan keyboard ergonomis.
- Implementasi aturan 5 menit istirahat setiap 1 jam.
- Konsultasi dengan dokter okupasi.

### 1.3 Budaya Kerja di Industri 4.0

#### A. Transformasi Budaya Kerja
Revolusi Industri 4.0 mengubah cara kita bekerja melalui:
- **Otomatisasi**: AI dan robotik menggantikan pekerjaan rutin.
- **Digitalisasi**: Semua aspek terhubung via IoT.
- **Virtual Collaboration**: Tim tersebar secara geografis (remote work).

#### B. Nilai-nilai Budaya Kerja Modern
1. **Growth Mindset** – Memandang kegagalan sebagai peluang belajar (Carol Dweck, 2006).
2. **Radical Candor** – Memberikan umpan balik yang jujur dan peduli (Kim Scott, 2017).
3. **Psychological Safety** – Kondisi tim di mana setiap orang merasa aman untuk berbicara tanpa takut dihukum (Google Project Aristotle, 2015).
4. **Agile Values** – Individu dan interaksi lebih penting daripada proses dan tools.

#### C. Budaya Kerja di Perusahaan Teknologi Terkenal
- **Google**: "20% time" – karyawan boleh menghabiskan 20% waktu untuk proyek personal.
- **Netflix**: "Freedom & Responsibility" – tidak ada aturan cuti, tetapi harus bertanggung jawab.
- **Spotify**: "Squad, Tribe, Chapter, Guild" – struktur organisasi yang fleksibel dan otonom.
- **Tokopedia**: "Mekari" (pembelajaran berkelanjutan) dengan budget training tahunan.

#### D. Membangun Budaya Kerja Positif di Tim Kecil
1. **Daily Stand-up** (15 menit) – setiap pagi: apa yang sudah dikerjakan, akan dikerjakan, dan hambatan.
2. **Retrospective Mingguan** – evaluasi apa yang berjalan baik dan buruk, serta rencana perbaikan.
3. **Pair Programming** – dua orang bekerja bersama di satu workstation (bergantian sebagai driver dan navigator).
4. **Knowledge Sharing** – presentasi internal rutin tentang teknologi baru.

### 1.4 Prosedur Kerja dan Standar Operasional

#### A. Anatomi SOP yang Baik
SOP yang efektif harus mengandung:
1. **Judul dan Nomor Dokumen**: Contoh: SOP-GIT-001.
2. **Tujuan**: Mengapa prosedur ini dibuat.
3. **Ruang Lingkup**: Untuk siapa dan di mana prosedur berlaku.
4. **Referensi**: Dokumen terkait (kebijakan, regulasi).
5. **Definisi**: Istilah penting yang digunakan.
6. **Langkah-langkah**: Detail dan berurutan, menggunakan diagram alur jika perlu.
7. **Dokumentasi**: Formulir, log, atau template yang digunakan.
8. **Revisi**: Tanggal pembaruan dan riwayat perubahan.

#### B. SOP Pengembangan Software (Contoh Lengkap)
**SOP: Penggunaan Git dan Github**

| Langkah | Aktivitas | Detail |
|---------|-----------|--------|
| 1 | Setup Repository | Clone repository menggunakan `git clone [url]` |
| 2 | Buat Branch | Buat branch baru dengan nama fitur: `git checkout -b feature/nama-fitur` |
| 3 | Commit | Lakukan commit dengan pesan yang jelas (format: `[type] deskripsi singkat`) |
| 4 | Push | `git push origin feature/nama-fitur` |
| 5 | Pull Request | Buat PR ke branch `develop` dan minta review minimal 1 orang |
| 6 | Review | Reviewer memberi komentar dan approve |
| 7 | Merge | Setelah approve, lakukan squash merge dan hapus branch |

**Code Commit Message Guidelines** (Conventional Commits):
```
feat: menambahkan fitur login
fix: memperbaiki bug pada validasi email
docs: memperbarui README
style: memperbaiki indentasi
refactor: merapikan struktur kode
test: menambahkan unit test
chore: mengupdate dependency
```

#### C. Workflow Manajemen Insiden (Incident Response Plan)
1. **Deteksi** – Monitoring tools (Prometheus, New Relic) mendeteksi anomali.
2. **Klasifikasi** – Tentukan tingkat keparahan (P1: kritis, P2: tinggi, P3: sedang, P4: rendah).
3. **Respons** – Tim on-call mengambil alih, komunikasi dengan stakeholder.
4. **Investigasi** – Cari akar masalah (root cause analysis).
5. **Resolusi** – Terapkan perbaikan sementara atau permanen.
6. **Post-Mortem** – Dokumen kronologi, penyebab, dan langkah pencegahan.

### 1.6 Manajemen Tools Pengembangan

#### A. Evaluasi dan Pemilihan Tools
Proses pemilihan tools tidak boleh asal. Gunakan kerangka **Technology Selection Framework**:

1. **Requirement Fit** – Apakah tools sesuai dengan kebutuhan proyek?
2. **Ecosystem & Community** – Seberapa besar komunitas dan dukungan?

4. **Cost** – Lisensi, biaya hosting, dan maintenance.
5. **Integration** – Seberapa mudah integrasi dengan tools lain?

#### B. Daftar Tools Populer dan Fungsinya

### 1.7 Manajemen Aset (Hardware, Software, Data)

#### A. Klasifikasi Aset
1. **Hardware Asset**: Server, laptop, monitor, switch, kabel, UPS.
2. **Software Asset**: Lisensi OS, IDE, database, library berbayar.
3. **Data Asset**: Kode sumber, basis data, dokumen, konfigurasi, user data.

#### B. Siklus Hidup Aset
1. **Perencanaan** – Kebutuhan aset berdasarkan roadmap proyek.
2. **Pengadaan** – Pembelian, leasing, atau open source.
3. **Pemeliharaan** – Update, perbaikan, dan pemantauan.
4. **Dekomisioning** – Penghapusan, recycling, atau disposal aman.

#### C. Software Asset Management (SAM)
Menurut ISO 19770, SAM adalah praktik untuk mengelola dan mengoptimalkan penggunaan software.

**Langkah SAM**:
1. Inventarisasi semua software yang digunakan.
2. Audit lisensi vs deployment.
3. Implementasi kebijakan penggunaan software.
4. Pelatihan karyawan tentang lisensi.
5. Pembaruan dan pembaharuan lisensi tepat waktu.

**Contoh Kasus**: Sebuah perusahaan menggunakan Microsoft Office di 100 komputer, tetapi hanya memiliki 80 lisensi. Solusi: lakukan audit, hapus yang tidak digunakan, atau beli lisensi tambahan.

#### D. Manajemen Data dan Backup
- **Prinsip 3-2-1 Backup**: 
  - 3 salinan data.
  - 2 media berbeda (local + cloud).
  - 1 salinan di lokasi berbeda (offsite).
- **Encryption**: Data sensitif harus dienkripsi (AES-256).
- **Retention Policy**: Berapa lama data disimpan (misal: 7 tahun untuk transaksi keuangan).
- **Disposal**: Gunakan software seperti DBAN untuk menghapus data di hard disk sebelum dibuang.

### 1.9 Analisis Algoritma: Kompleksitas Waktu dan Ruang

#### A. Pengukuran Kinerja Algoritma
Algoritma harus dievaluasi berdasarkan:
1. **Time Complexity** – Waktu eksekusi berdasarkan input size (n).
2. **Space Complexity** – Memori yang digunakan.
3. **Scalability** – Bagaimana performa saat n membesar.

#### B. Notasi Big-O, Theta, dan Omega
- **Big-O (O)**: Batas atas (worst-case).
- **Omega (Ω)**: Batas bawah (best-case).
- **Theta (θ)**: Batas ketat (average-case).

#### C. Tabel Kompleksitas Waktu
| Notasi | Nama | Contoh Algoritma | Keterangan |
|--------|------|------------------|------------|
| O(1) | Konstan | Akses elemen array | Waktu tetap, tidak terpengaruh n |
| O(log n) | Logaritmik | Binary search | Data dibelah dua tiap langkah |
| O(n) | Linear | Linear search, iterasi biasa | Waktu proporsional terhadap n |
| O(n log n) | Linieritmik | Merge sort, Quick sort | Efisien untuk sorting data besar |
| O(n²) | Kuadratik | Bubble sort, nested loop | Memburuk cepat, hindari untuk n besar |
| O(2^n) | Eksponensial | Fibonacci naive | Sangat lambat, tidak praktis |
| O(n!) | Faktorial | Traveling salesman | Tidak praktis untuk n > 10 |

#### D. Contoh Analisis Kode

**Contoh 1: Linear Search**
```python
def linear_search(arr, target):
    for i in range(len(arr)):   # O(n) - iterasi n kali
        if arr[i] == target:
            return i
    return -1
# Time Complexity: O(n), Space Complexity: O(1)
```

**Contoh 2: Binary Search (Iteratif)**
```python
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1
    while low <= high:          # O(log n) - setiap iterasi setengahkan ruang
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
# Time Complexity: O(log n), Space Complexity: O(1)
```

**Contoh 3: Bubble Sort**
```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):          # O(n) outer loop
        for j in range(0, n-i-1): # O(n) inner loop
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
# Time Complexity: O(n²), Space Complexity: O(1)
```

#### E. Amortized Analysis
Digunakan untuk struktur data yang jarang memiliki operasi berat, tetapi rata-rata ringan (contoh: ArrayList).

**Contoh**: ArrayList di Java/Javascript menambah kapasitas ketika penuh (resize).
- Operasi push average: O(1)
- Operasi push worst-case saat resize: O(n)
- Amortized: O(1) per operasi.

## BAB 2: TEKNOLOGI JARINGAN KOMPUTER

### 2.1 Sejarah dan Evolusi Jaringan

#### A. Tahapan Perkembangan Jaringan
1. **Era 1960-an (ARPANET)** – Dikembangkan oleh DARPA (USA). Awalnya menghubungkan 4 universitas menggunakan packet switching.
2. **Era 1970-an (TCP/IP)** – Vint Cerf dan Bob Kahn merumuskan protokol TCP/IP yang menjadi standar internet.
3. **Era 1980-an (LAN & Ethernet)** – Ethernet (IEEE 802.3) memungkinkan jaringan lokal dengan topologi bus.
4. **Era 1990-an (World Wide Web)** – Tim Berners-Lee menciptakan HTTP dan HTML, internet meledak secara komersial.
5. **Era 2000-an (Mobile & Broadband)** – 3G, 4G, Wi-Fi memungkinkan akses di mana saja.
6. **Era 2010-2020 (Cloud & IoT)** – Jaringan server global (AWS, Azure), miliaran perangkat IoT terhubung.
7. **Era 2020-sekarang (5G, SDN, AI-Networking)** – Jaringan software-defined, otomatisasi dengan AI, latency rendah.

#### B. Dampak Perkembangan Jaringan
- **Komunikasi**: Dari surat ke email, video call real-time.
- **Bisnis**: E-commerce, remote work, digital marketing.
- **Pendidikan**: E-learning, MOOC (Coursera, edX).
- **Hiburan**: Streaming (Netflix, YouTube), multiplayer gaming.

### 2.2 Fundamental Jaringan: Model OSI & TCP/IP

#### A. Model OSI (Open System Interconnection)
Dikembangkan oleh ISO, memiliki 7 lapisan yang saling berfungsi:

| No | Lapisan | Fungsi Utama | Contoh Protokol/Perangkat |
|----|---------|--------------|---------------------------|
| 7 | Application | Interface pengguna | HTTP, FTP, SMTP, DNS |
| 6 | Presentation | Translasi data (enkripsi, kompresi) | SSL/TLS, JPEG, MPEG |
| 5 | Session | Mengelola sesi komunikasi | NetBIOS, RPC |
| 4 | Transport | Segmentasi dan reliabilitas | TCP, UDP |
| 3 | Network | Routing dan pengalamatan | IP, ICMP, Router |
| 2 | Data Link | Framing dan akses medium | Ethernet, Switch, Bridge |
| 1 | Physical | Bit stream, sinyal fisik | Kabel, Hub, NIC |

**Mnemonik**: "Please Do Not Throw Sausage Pizza Away" (dari Physical ke Application).

#### B. Model TCP/IP (4 Lapisan)
| No | Lapisan | Fungsi | Protokol |
|----|---------|--------|----------|
| 4 | Application | Kombinasi OSI 5-7 | HTTP, DNS, FTP, SMTP |
| 3 | Transport | Sama dengan OSI layer 4 | TCP, UDP |
| 2 | Internet | Sama dengan OSI layer 3 | IP, ICMP, ARP |
| 1 | Network Access | Sama dengan OSI 1-2 | Ethernet, Wi-Fi, PPP |

**Perbedaan Utama**:
- OSI lebih teoritis, TCP/IP lebih praktis dan digunakan di internet.
- TCP/IP menggabungkan lapisan Application, Presentation, Session.
- TCP/IP memiliki lapisan Network Access yang menggabungkan Data Link dan Physical.

### 2.3 Hardware Jaringan: Analisis Mendalam

#### A. Komponen Komputer untuk Jaringan
1. **CPU (Central Processing Unit)**:
   - Server membutuhkan CPU dengan banyak core (misal: Intel Xeon, AMD EPYC).
   - Kecepatan clock (GHz) dan cache mempengaruhi throughput.
   - Contoh: Untuk server web, minimal 4 core 2.5GHz.

2. **RAM (Random Access Memory)**:
   - Jaringan intensif data membutuhkan RAM besar untuk buffer dan caching.
   - Contoh: Server database membutuhkan 64GB+ RAM.

3. **Network Interface Card (NIC)**:
   - Kecepatan: 10/100/1000 Mbps (Gigabit) hingga 10/25/40 Gbps.
   - Duplex: Half-duplex vs Full-duplex.
   - Jumlah port: 1-8 port per kartu.

4. **Switch/Router**:
   - Switch: backplane capacity, forwarding rate (packet per second).
   - Router: routing table size, NAT throughput, VPN support.

5. **Storage**:
   - Network Attached Storage (NAS) untuk sharing file.
   - SSD vs HDD: throughput (MB/s) dan IOPS (Input/Output Operations per Second).

#### B. Analisis Kebutuhan Hardware Berdasarkan Kasus
**Kasus: Sekolah dengan 200 komputer**
- 1 Server (CPU 8 core, RAM 32GB, SSD 2TB) untuk aplikasi dan DHCP.
- 5 Switch 48-port Gigabit.
- 1 Router dengan throughput >500 Mbps.
- 1 NAS untuk backup.

### 2.4 Topologi Jaringan: Kelebihan, Kekurangan, dan Penerapan

| Topologi | Deskripsi | Kelebihan | Kekurangan | Contoh Penerapan |
|----------|-----------|-----------|------------|------------------|
| **Bus** | Semua perangkat terhubung ke satu kabel utama | Hemat kabel | Single point of failure, sulit troubleshoot | Jaringan kecil di lab |
| **Star** | Semua perangkat terhubung ke switch/hub central | Mudah dikelola, isolasi error | Bergantung pada switch | Jaringan kantor, sekolah |
| **Ring** | Perangkat membentuk lingkaran, data mengalir satu arah | Tidak ada collision | Jika satu node mati, seluruh jaringan terganggu | Fiber Distributed Data Interface (FDDI) |
| **Mesh** | Setiap perangkat terhubung ke semua perangkat lain | Redundansi tinggi | Mahal dan kompleks | Jaringan militer, backbone internet |
| **Tree** | Kombinasi star dan bus (hierarki) | Skalabel | Maintenance kompleks | Jaringan kampus, ISP |
| **Hybrid** | Kombinasi 2 atau lebih topologi | Fleksibel | Kompleks | Perusahaan multinasional |

### 2.5 Perangkat Jaringan Aktif dan Pasif

#### A. Perangkat Aktif (Membutuhkan Listrik)
1. **Switch**:
   - **Layer 2**: Beroperasi di Data Link, menggunakan MAC address.
   - **Layer 3**: Bisa melakukan routing (Multi-layer switch).
   - Fitur: VLAN, QoS, STP, Port Mirroring.

2. **Router**:
   - Menghubungkan 2 atau lebih network yang berbeda.
   - Routing protocol: Static, RIP, OSPF, BGP.
   - NAT (Network Address Translation) – menerjemahkan IP private ke public.

3. **Access Point (AP)**:
   - Menyediakan koneksi wireless ke client.
   - Standar: 802.11a/b/g/n/ac/ax (Wi-Fi 6).
   - Mode: Bridge, Repeater, Mesh.

4. **Firewall**:
   - Filtering berdasarkan IP, port, aplikasi.
   - Jenis: Packet filter, Stateful inspection, Application gateway (Proxy).

5. **Modem**:
   - Modulasi dan demodulasi sinyal (analog ke digital).
   - Jenis: ADSL, Cable, Fiber (GPON).

#### B. Perangkat Pasif (Tidak Membutuhkan Listrik)
1. **Kabel**:
   - **UTP (Unshielded Twisted Pair)**: Cat5e, Cat6, Cat6a, Cat7.
   - **STP (Shielded Twisted Pair)**: Pelindung untuk lingkungan dengan interferensi.
   - **Fiber Optic**: Singlemode (jarak jauh) vs Multimode (jarak pendek).

2. **Connector**:
   - RJ45 (untuk kabel UTP/STP).
   - SC, LC, ST (untuk fiber optic).

3. **Patch Panel**:
   - Panel untuk mengorganisasi dan mengelola kabel.

4. **Wallplate, Rack, Cable Tray**:
   - Infrastruktur untuk menata perangkat dan kabel.

### 2.6 IP Address, Subnetting, dan VLSM

#### A. Struktur IP Address (IPv4)
- 32 bit, dibagi menjadi 4 oktet (masing-masing 8 bit).
- Contoh: `192.168.1.10`
- Bagian: **Network ID** + **Host ID**.
- Subnet mask menentukan mana bit network dan host.

#### B. Kelas IP Address
| Kelas | IP Range | Subnet Mask | Penggunaan |
|-------|----------|-------------|------------|
| A | 1.0.0.0 – 126.255.255.255 | /8 (255.0.0.0) | Jaringan sangat besar |
| B | 128.0.0.0 – 191.255.255.255 | /16 (255.255.0.0) | Jaringan menengah |
| C | 192.0.0.0 – 223.255.255.255 | /24 (255.255.255.0) | Jaringan kecil |
| D | 224.0.0.0 – 239.255.255.255 | - | Multicast |
| E | 240.0.0.0 – 255.255.255.255 | - | Eksperimental |

#### C. IP Private (RFC 1918)
- 10.0.0.0/8 (10.0.0.0 – 10.255.255.255)
- 172.16.0.0/12 (172.16.0.0 – 172.31.255.255)
- 192.168.0.0/16 (192.168.0.0 – 192.168.255.255)

#### D. Subnetting (Contoh Lengkap)
**Kasus**: Diberikan network `192.168.1.0/24`. Dibutuhkan 4 subnet, masing-masing dengan minimal 30 host.

**Langkah**:
1. Jumlah subnet = 4 → butuh 2 bit untuk subnet (2² = 4).
2. Subnet mask baru: /24 + 2 = /26 (255.255.255.192).
3. Jumlah host per subnet: 2^(32-26) - 2 = 2^6 - 2 = 62 host per subnet.

**Daftar Subnet**:
| Subnet | Network | Range Host | Broadcast |
|--------|---------|------------|-----------|
| 1 | 192.168.1.0/26 | 1 – 62 | 63 |
| 2 | 192.168.1.64/26 | 65 – 126 | 127 |
| 3 | 192.168.1.128/26 | 129 – 190 | 191 |
| 4 | 192.168.1.192/26 | 193 – 254 | 255 |

#### E. VLSM (Variable Length Subnet Mask)
Membagi subnet dengan ukuran berbeda sesuai kebutuhan.

**Kasus**: 
- Subnet A: 100 host → butuh /25 (128 host)
- Subnet B: 50 host → butuh /26 (64 host)
- Subnet C: 20 host → butuh /27 (32 host)

**Alokasi**:
1. Network: `192.168.1.0/24`
2. A: `192.168.1.0/25` (192.168.1.0 – 192.168.1.127)
3. B: `192.168.1.128/26` (192.168.1.128 – 192.168.1.191)
4. C: `192.168.1.192/27` (192.168.1.192 – 192.168.1.223)
5. Sisa: 192.168.1.224 – 255.

### 2.7 Troubleshooting Jaringan: Metodologi dan Tools

#### A. Metodologi Troubleshooting (Model OSI)
1. **Physical (Layer 1)** – Periksa kabel, konektor, indikator LED.
2. **Data Link (Layer 2)** – Periksa MAC address, VLAN, duplex mismatch.
3. **Network (Layer 3)** – Ping, routing, IP conflict.
4. **Transport (Layer 4)** – Port terbuka? Firewall block?
5. **Application (Layer 5-7)** – DNS resolution, service running?

#### B. Perintah Dasar (Windows/Linux)
| Perintah | Fungsi | Contoh |
|----------|--------|--------|
| `ping` | Uji konektivitas layer 3 | `ping 8.8.8.8` |
| `tracert` / `traceroute` | Lacak rute paket | `tracert google.com` |
| `ipconfig` / `ifconfig` | Lihat konfigurasi IP | `ipconfig /all` |
| `netstat` | Lihat koneksi aktif | `netstat -an` |
| `nslookup` | Cek DNS | `nslookup google.com` |
| `arp -a` | Lihat tabel ARP | `arp -a` |
| `route print` | Lihat tabel routing | `route print` |

#### C. Alat Bantu Lanjutan
- **Wireshark**: Packet sniffer untuk analisis detail.
- **Nmap**: Port scanning dan discovery.
- **MTR** (My TraceRoute): Kombinasi ping + traceroute real-time.
- **Speedtest**: Mengukur bandwidth internet.
- **PRTG / SolarWinds**: Monitoring jaringan enterprise.

#### D. Skenario Troubleshooting
**Masalah**: User tidak bisa mengakses internet, tetapi bisa ping ke router.

**Analisis**:
1. Cek konfigurasi DNS – coba `nslookup google.com`.
2. Jika gagal, DNS server bermasalah → ganti ke 8.8.8.8.
3. Cek routing di router – apakah ada default gateway ke ISP?
4. Cek NAT – apakah router melakukan NAT dengan benar?
5. Hubungi ISP jika masih gagal.

### 2.8 Keamanan Jaringan Dasar

#### A. Ancaman Jaringan
1. **Malware**: Virus, worm, trojan, ransomware.
2. **Man-in-the-Middle (MITM)**: Penyadapan komunikasi.
3. **Denial of Service (DoS)**: Membanjiri server dengan lalu lintas.
4. **Phishing**: Mencuri kredensial via situs palsu.
5. **Packet Sniffing**: Menangkap data yang tidak terenkripsi.

#### B. Teknik Keamanan
1. **Firewall**:
   - Gunakan iptables (Linux) atau Windows Firewall.
   - Aturan: deny all incoming, allow only necessary ports.
2. **Encryption**:
   - HTTPS (TLS/SSL) untuk web.
   - VPN (IPsec, OpenVPN) untuk koneksi remote.
3. **Authentication**:
   - 2FA (Two-Factor Authentication).
   - RADIUS / TACACS+ untuk AAA (Authentication, Authorization, Accounting).
4. **Intrusion Detection System (IDS)**:
   - Snort, Suricata.
   - Monitoring anomali lalu lintas.

#### C. Praktik Terbaik
- Ganti password default.
- Nonaktifkan port yang tidak digunakan.
- Lakukan update firmware secara rutin.
- Segmentasi jaringan (VLAN) untuk memisahkan server dan client.
- Audit keamanan berkala (penetration testing).

### 3.11 Proyek: Game Console Sederhana

**Tujuan**: Membangun game tebak angka dengan menu utama.

**Spesifikasi**:
1. Menu: 1) Main, 2) Lihat High Score, 3) Keluar.
2. Game: Komputer menghasilkan angka acak (1-100), pemain menebak.
3. High Score disimpan dalam file.

**Implementasi (Python)**:
```python
import random
import json
import os

HIGH_SCORE_FILE = "highscore.json"

def load_highscore():
    if os.path.exists(HIGH_SCORE_FILE):
        with open(HIGH_SCORE_FILE, "r") as f:
            return json.load(f)
    return {"tebakan_terbaik": float('inf'), "nama": ""}

def save_highscore(tebakan, nama):
    high = load_highscore()
    if tebakan < high["tebakan_terbaik"]:
        high["tebakan_terbaik"] = tebakan
        high["nama"] = nama
        with open(HIGH_SCORE_FILE, "w") as f:
            json.dump(high, f)

def main_game(nama):
    target = random.randint(1, 100)
    tebakan = 0
    print(f"{nama}, tebak angka 1-100!")

    while True:
        try:
            guess = int(input("Tebakanmu: "))
            tebakan += 1
            if guess < target:
                print("Terlalu kecil!")
            elif guess > target:
                print("Terlalu besar!")
            else:
                print(f"Benar! Jawabannya {target}")
                print(f"Kamu menebak {tebakan} kali.")
                save_highscore(tebakan, nama)
                break
        except ValueError:
            print("Masukkan angka yang valid!")

def main_menu():
    nama = input("Masukkan nama kamu: ")
    while True:
        print("\n=== GAME TEBAK ANGKA ===")
        print("1. Main")
        print("2. Lihat High Score")
        print("3. Keluar")
        pilihan = input("Pilih menu: ")

        if pilihan == "1":
            main_game(nama)
        elif pilihan == "2":
            high = load_highscore()
            if high["nama"]:
                print(f"High Score: {high['tebakan_terbaik']} tebakan oleh {high['nama']}")
            else:
                print("Belum ada high score.")
        elif pilihan == "3":
            print("Sampai jumpa!")
            break
        else:
            print("Pilihan tidak valid!")

if __name__ == "__main__":
    main_menu()
```

### 4.2 Kelas dan Objek: Blueprint & Instance

```python
class Mobil:
```

### 4.5 Pewarisan (Inheritance) dan Hierarki Kelas

#### A. Konsep Dasar
Pewarisan memungkinkan kelas turunan (child) mewarisi atribut dan metode dari kelas induk (parent).

**Contoh (Python)**:
```python
class Hewan:
    def __init__(self, nama):
        self.nama = nama

    def suara(self):
        return "Hewan mengeluarkan suara"

class Kucing(Hewan):  # Kucing mewarisi Hewan
    def suara(self):  # Override
        return "Meong!"

class Anjing(Hewan):
    def suara(self):
        return "Guk! Guk!"

kucing = Kucing("Tom")
anjing = Anjing("Spike")
print(kucing.nama)    # Tom (dari parent)
print(kucing.suara()) # Meong!
print(anjing.suara()) # Guk! Guk!
```

#### B. Pewarisan di Java
```java
class Hewan {
    protected String nama;
    public Hewan(String nama) {
        this.nama = nama;
    }
    public String suara() {
        return "Hewan mengeluarkan suara";
    }
}

class Kucing extends Hewan {
    public Kucing(String nama) {
        super(nama);  // Panggil constructor parent
    }
    @Override
    public String suara() {
        return "Meong!";
    }
}
```

#### C. Multiple Inheritance (Python)
Python mendukung multiple inheritance (dengan MRO – Method Resolution Order).

```python
class Flyer:

        return "Terbang!"

class Swimmer:
    def berenang(self):
        return "Berenang!"

class Duck(Flyer, Swimmer):
    pass

bebek = Duck()

print(bebek.berenang()) # Berenang!
```

**Catatan**: Java tidak mendukung multiple inheritance, menggunakan interface.

```python
class Anak:

        self.umur = umur
```

### 4.6 Polimorfisme (Static & Dynamic)

#### A. Static Polymorphism (Overloading)
Method dengan nama sama tetapi parameter berbeda.

**Contoh (Java)**:
```java
class Calculator {
    public int tambah(int a, int b) {
        return a + b;
    }

    public int tambah(int a, int b, int c) {
        return a + b + c;
    }

    public double tambah(double a, double b) {
        return a + b;
    }
}
```

**Contoh (Python) – tidak perlu overload, gunakan default params atau `*args`**:
```python
class Calculator:
    def tambah(self, *args):
        return sum(args)

print(calc.tambah(1, 2, 3))   # 6
```

#### B. Dynamic Polymorphism (Overriding)
Method di subclass mengganti implementasi parent.

```python
class Bentuk:
    def luas(self):
        return 0

class Persegi(Bentuk):
    def __init__(self, sisi):
        self.sisi = sisi
    def luas(self):
        return self.sisi ** 2

class Lingkaran(Bentuk):
    def __init__(self, radius):
        self.radius = radius
    def luas(self):
        return 3.14 * self.radius ** 2

# Polimorfisme
bentuk_bentuk = [Persegi(5), Lingkaran(7)]
for b in bentuk_bentuk:
    print(b.luas())  # 25, 153.86
```

#### C. Polymorphic Function
```python
def cetak_luas(bentuk):
    print(f"Luas: {bentuk.luas()}")

cetak_luas(Persegi(4))    # Luas: 16
cetak_luas(Lingkaran(3))  # Luas: 28.26
```

### 4.7 Abstraksi (Abstract Class & Interface)

```python
from abc import ABC, abstractmethod

class Kendaraan(ABC):

class Mobil(Kendaraan):

# k = Kendaraan()  # ERROR: cannot instantiate

```

```java
abstract class Kendaraan {

}
```

### 4.8 Relasi Antar Kelas (Association, Aggregation, Composition)

#### A. Association (Asosiasi)
Relasi sederhana antar objek yang saling mengenal, tetapi independen.

```python
class Dosen:
    def __init__(self, nama):

class Mahasiswa:
    def __init__(self, nama):

        self.dosen = dosen
```

#### B. Aggregation (Agregasi)
Relasi "has-a" di mana objek memiliki objek lain, tetapi keduanya bisa berdiri sendiri.

```python
class Mesin:
    def __init__(self, jenis):
        self.jenis = jenis
```

#### C. Composition (Komposisi)
Relasi "part-of" di mana objek dikandung oleh objek lain dan tidak bisa berdiri sendiri.

```python
class Roda:

class Sepeda:

# Jika sepeda dihapus, roda juga ikut dihapus
```

| Relasi | Ketergantungan | Contoh |

### 4.11 Design Pattern Dasar (Singleton, Factory, Observer)

#### A. Singleton Pattern
Memastikan hanya ada satu instance dari suatu kelas.

```python
class Singleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

s1 = Singleton()
s2 = Singleton()
print(s1 is s2)  # True
```

#### B. Factory Pattern
Memisahkan pembuatan objek dari penggunaan.

```python
class Shape:
    def draw(self):
        pass

class Circle(Shape):
    def draw(self):
        print("Draw Circle")

class Square(Shape):
    def draw(self):
        print("Draw Square")

class ShapeFactory:
    def create_shape(self, type):
        if type == "circle":
            return Circle()
        elif type == "square":
            return Square()
        else:
            raise ValueError("Unknown shape")

factory = ShapeFactory()
shape = factory.create_shape("circle")
shape.draw()  # Draw Circle
```

#### C. Observer Pattern (Event-Driven)
```python
class Subject:
    def __init__(self):
        self._observers = []

    def attach(self, observer):
        self._observers.append(observer)

    def notify(self, data):
        for observer in self._observers:
            observer.update(data)

class Observer:
    def update(self, data):
        print(f"Received: {data}")

subject = Subject()
obs1 = Observer()
obs2 = Observer()
subject.attach(obs1)
subject.attach(obs2)
subject.notify("Event terjadi!")  # Kedua observer mendapat notifikasi
```

### 4.12 Proyek: Simple RPG Game

**Tujuan**: Membangun RPG sederhana dengan class Player, Monster, dan Battle System.

**Kelas**:
1. `Character` (abstract base)
   - `name`, `hp`, `attack_power`
   - `attack(target)`, `take_damage(amount)`, `is_alive()`
2. `Player` (subclass Character)
   - `level`, `exp`, `heal()`
3. `Monster` (subclass Character)
   - `type`, `reward_exp`

**Implementasi (Python)**:
```python
from abc import ABC, abstractmethod
import random

class Character(ABC):
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.max_hp = hp
        self.hp = hp
        self.attack_power = attack_power

    @abstractmethod
    def special_ability(self):
        pass

    def attack(self, target):
        damage = random.randint(self.attack_power - 3, self.attack_power + 3)
        if damage < 0: damage = 0
        target.take_damage(damage)
        print(f"{self.name} menyerang {target.name} dengan {damage} damage!")

    def take_damage(self, damage):
        self.hp -= damage
        if self.hp < 0: self.hp = 0
        print(f"{self.name} terkena serangan, HP tersisa {self.hp}")

    def is_alive(self):
        return self.hp > 0

class Player(Character):
    def __init__(self, name):
        super().__init__(name, 100, 15)
        self.level = 1
        self.exp = 0

    def special_ability(self):
        heal_amount = 20 + (self.level * 5)
        self.hp = min(self.max_hp + self.level * 10, self.hp + heal_amount)
        print(f"{self.name} menggunakan Healing! HP bertambah {heal_amount}")

    def gain_exp(self, amount):
        self.exp += amount
        if self.exp >= 100:
            self.level_up()

    def level_up(self):
        self.level += 1
        self.exp = 0
        self.max_hp += 10
        self.hp = self.max_hp
        self.attack_power += 5
        print(f"{self.name} naik level! Level {self.level}")

class Monster(Character):
    def __init__(self, name, hp, attack_power, exp_reward):
        super().__init__(name, hp, attack_power)
        self.exp_reward = exp_reward

    def special_ability(self):
        print(f"{self.name} mengaum dengan keras!")

def battle(player, monster):
    print(f"\n=== {monster.name} muncul! ===")
    while player.is_alive() and monster.is_alive():
        print("\n1. Serang\n2. Special Ability\n3. Lari")
        choice = input("Pilih aksi: ")

        if choice == "1":
            player.attack(monster)
        elif choice == "2":
            player.special_ability()
        elif choice == "3":
            print("Kamu melarikan diri!")
            return False

        if monster.is_alive():
            monster.attack(player)
        else:
            print(f"{monster.name} kalah!")
            player.gain_exp(monster.exp_reward)
            return True

    if not player.is_alive():
        print("Kamu mati! Game Over")
        return False

# Game loop
player = Player("Hero")
monsters = [
    Monster("Slime", 30, 5, 20),
    Monster("Goblin", 40, 8, 40),
    Monster("Skeleton", 50, 12, 60)
]

for monster in monsters:
    if not battle(player, monster):
        break
    print(f"Player HP: {player.hp}/{player.max_hp}, Level: {player.level}")
```
