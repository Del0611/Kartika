# Materi Kelas XII: CI/CD, Deployment, Monitoring, Logging, dan DevSecOps

## 1. Pengertian Capaian Pembelajaran

Pada akhir Kelas XII, peserta didik diharapkan mampu merancang, membangun, dan menjalankan proses pengembangan aplikasi secara profesional. Peserta didik tidak hanya belajar membuat aplikasi, tetapi juga mempelajari cara menguji, memperbarui, mengamankan, dan memantau aplikasi agar dapat digunakan dengan baik.

Materi ini berkaitan dengan praktik pengembangan perangkat lunak di dunia kerja, khususnya dalam bidang Software Development, DevOps, dan keamanan aplikasi.

## 2. Continuous Integration dan Continuous Delivery/Deployment (CI/CD)

![CI/CD Pipeline](https://placehold.co/900x400/172554/FFFFFF?text=CI%2FCD+Pipeline%3A+Code+%E2%86%92+Build+%E2%86%92+Test+%E2%86%92+Deploy)

### A. Pengertian CI/CD

CI/CD merupakan metode untuk mengotomatisasi sebagian proses pengembangan dan pengiriman aplikasi. Dengan CI/CD, proses pemeriksaan kode, pengujian, dan pengiriman aplikasi dapat dilakukan secara lebih cepat dan teratur.

**Continuous Integration (CI)** adalah proses menggabungkan perubahan kode dari beberapa programmer ke dalam satu repositori serta menjalankan pemeriksaan atau pengujian secara otomatis.

**Continuous Delivery** adalah proses menyiapkan aplikasi agar selalu siap dirilis ke lingkungan produksi.

**Continuous Deployment** adalah proses menerapkan perubahan kode yang telah lolos pemeriksaan dan pengujian secara otomatis ke lingkungan produksi.

### B. Tahapan Pipeline CI/CD

1. **Code:** Programmer menulis atau memperbarui kode program.
2. **Build:** Sistem menyiapkan aplikasi agar dapat dijalankan.
3. **Test:** Sistem menjalankan pengujian untuk mendeteksi kesalahan.
4. **Deploy:** Aplikasi dikirim atau diterapkan ke server.
5. **Monitor:** Aplikasi dipantau setelah dijalankan.

Pipeline merupakan rangkaian tahapan tersebut yang dapat dijalankan secara otomatis menggunakan alat seperti GitHub Actions, GitLab CI/CD, atau Jenkins.

### C. Contoh Penerapan

Seorang siswa membuat aplikasi absensi berbasis web. Kode program disimpan di GitHub. Ketika siswa memperbarui kode, GitHub Actions dapat menjalankan pemeriksaan otomatis. Jika pemeriksaan berhasil, aplikasi dapat disiapkan untuk dirilis atau diterapkan ke server sesuai konfigurasi pipeline.

## 3. Deployment Terkontrol

![Deployment Strategies](https://placehold.co/900x400/164E63/FFFFFF?text=Controlled+Deployment+and+Rollback)

### A. Pengertian Deployment

Deployment adalah proses memasang atau memperbarui aplikasi pada lingkungan tempat aplikasi dijalankan, misalnya server sekolah atau layanan cloud.

Deployment terkontrol dilakukan dengan perencanaan dan pengujian agar pembaruan aplikasi tidak menimbulkan gangguan yang tidak diperlukan.

### B. Jenis Strategi Deployment

**1. Blue-Green Deployment**

Strategi yang menggunakan dua lingkungan aplikasi. Lingkungan baru disiapkan dan diuji terlebih dahulu sebelum pengguna dialihkan dari lingkungan lama.

**2. Canary Deployment**

Strategi yang menerapkan versi baru kepada sebagian kecil pengguna terlebih dahulu. Jika hasilnya baik, pembaruan dapat diperluas ke lebih banyak pengguna.

**3. Rollback**

Proses mengembalikan aplikasi ke versi sebelumnya ketika versi terbaru mengalami masalah.

### C. Contoh Penerapan

Sekolah memiliki aplikasi absensi siswa yang sudah digunakan. Programmer ingin menambahkan fitur rekap kehadiran. Sebelum versi baru digunakan, programmer mengujinya terlebih dahulu. Jika terjadi kesalahan setelah pembaruan, programmer dapat melakukan rollback sesuai prosedur yang disiapkan.

## 4. Monitoring dan Logging Terpusat

![Monitoring Dashboard](https://placehold.co/900x400/14532D/FFFFFF?text=Application+Monitoring+and+Centralized+Logging)

### A. Pengertian Monitoring

Monitoring adalah proses memantau kondisi dan kinerja aplikasi, server, serta infrastruktur yang mendukungnya.

Monitoring dapat digunakan untuk:

- Memeriksa apakah aplikasi dapat diakses.
- Memantau penggunaan CPU dan memori.
- Mengukur waktu respons aplikasi.
- Mengetahui jumlah kesalahan yang terjadi.
- Memberikan peringatan ketika terjadi gangguan.

Salah satu alat yang dapat digunakan adalah Grafana untuk menampilkan data pemantauan dalam bentuk dashboard.

### B. Pengertian Logging

Logging adalah proses mencatat kejadian yang berlangsung pada aplikasi atau server. Catatan tersebut disebut log.

Contoh informasi yang dicatat meliputi waktu kejadian, jenis kesalahan, proses yang dijalankan, dan informasi teknis yang diperlukan untuk pemeriksaan.

Log harus dikelola dengan baik agar tidak menyimpan kata sandi, token, atau data pribadi yang tidak diperlukan.

### C. Pengertian Logging Terpusat

Logging terpusat adalah metode mengumpulkan log dari beberapa aplikasi atau server ke satu sistem agar lebih mudah dicari, diperiksa, dan dianalisis.

Salah satu contoh teknologi yang dapat dipelajari adalah ELK Stack, yang terdiri dari Elasticsearch, Logstash, dan Kibana.

### D. Perbedaan Monitoring dan Logging

Monitoring membantu menjawab pertanyaan, "Apakah aplikasi berjalan dengan baik?"

Logging membantu menjawab pertanyaan, "Apa yang terjadi ketika aplikasi mengalami masalah?"

Keduanya saling melengkapi untuk membantu menjaga keandalan aplikasi.

## 5. DevSecOps

![DevSecOps](https://placehold.co/900x400/581C87/FFFFFF?text=DevSecOps%3A+Development+%2B+Security+%2B+Operations)

### A. Pengertian DevSecOps

DevSecOps merupakan pendekatan yang mengintegrasikan keamanan ke dalam seluruh proses pengembangan dan pengoperasian aplikasi.

Keamanan tidak hanya diperiksa setelah aplikasi selesai dibuat, tetapi juga diterapkan sejak perencanaan, penulisan kode, pengujian, hingga deployment.

### B. Penerapan DevSecOps

Beberapa kegiatan yang termasuk dalam DevSecOps adalah:

1. Memeriksa kode untuk menemukan potensi kerentanan.
2. Memeriksa keamanan pustaka atau dependency yang digunakan.
3. Menyimpan token dan kunci API dengan aman.
4. Mengatur hak akses pengguna sesuai kebutuhan.
5. Memeriksa konfigurasi server dan aplikasi.
6. Menjalankan pengujian keamanan sebelum aplikasi dirilis.
7. Memperbaiki kerentanan yang ditemukan.

Alat yang dapat dipelajari antara lain GitHub Dependabot untuk membantu memeriksa pembaruan dependency dan CodeQL untuk analisis keamanan kode pada bahasa yang didukung.

### C. Contoh Penerapan

Dalam aplikasi absensi siswa, programmer harus memastikan bahwa siswa hanya dapat mengakses data yang menjadi haknya. Data guru dan administrator harus dilindungi menggunakan autentikasi dan pengaturan hak akses yang sesuai.

Selain itu, informasi rahasia seperti kata sandi database tidak boleh ditulis langsung ke dalam kode yang dipublikasikan di repositori.

## 6. Kerja Sama Tim Lintas Fungsi

Pengembangan aplikasi di dunia kerja umumnya melibatkan beberapa orang dengan tanggung jawab yang berbeda.

**Programmer atau Developer** bertugas membuat dan memperbaiki kode program.

**Quality Assurance (QA)** bertugas menguji aplikasi untuk menemukan kesalahan dan memastikan fitur berjalan sesuai kebutuhan.

**Tim Operations** bertugas membantu mengelola server, konfigurasi, dan lingkungan tempat aplikasi dijalankan.

**Tim Security** membantu memeriksa keamanan aplikasi dan infrastruktur.

Dalam proyek sekolah, siswa dapat membagi peran tersebut ke dalam kelompok. Setiap anggota bertanggung jawab atas tugasnya dan berkoordinasi dengan anggota lainnya.

Git dan GitHub dapat digunakan untuk mengelola perubahan kode, sedangkan dokumentasi dan komunikasi membantu mengurangi kesalahpahaman dalam pengerjaan proyek.

## 7. Dokumentasi Sistem

Dokumentasi sistem adalah kumpulan informasi tertulis yang menjelaskan cara kerja, penggunaan, pemasangan, dan pemeliharaan aplikasi.

Dokumentasi proyek dapat berisi:

- Nama dan tujuan aplikasi.
- Daftar teknologi yang digunakan.
- Persyaratan perangkat lunak dan perangkat keras.
- Cara memasang dan menjalankan aplikasi.
- Struktur folder dan repositori.
- Konfigurasi pipeline CI/CD.
- Prosedur deployment dan rollback.
- Cara membaca log dan memeriksa monitoring.
- Langkah pengamanan aplikasi.
- Hasil pengujian dan masalah yang ditemukan.

Dokumentasi yang baik membantu anggota tim lain memahami sistem dan melanjutkan pengembangan tanpa harus memulai dari awal.

## 8. Presentasi Solusi secara Profesional

Presentasi merupakan kegiatan menyampaikan hasil pekerjaan, menjelaskan keputusan teknis, dan menunjukkan bahwa aplikasi telah dibuat serta diuji.

Dalam presentasi proyek, peserta didik dapat menjelaskan:

1. Masalah yang ingin diselesaikan.
2. Tujuan dan fungsi aplikasi.
3. Teknologi yang digunakan.
4. Proses pengembangan dan pipeline CI/CD.
5. Strategi deployment yang diterapkan.
6. Monitoring, logging, dan keamanan aplikasi.
7. Hasil pengujian.
8. Kendala dan cara mengatasinya.
9. Kesimpulan dan rencana pengembangan berikutnya.

Presentasi sebaiknya disampaikan secara runtut dengan demonstrasi aplikasi dan bukti pengujian yang relevan.

## 9. Contoh Proyek Akhir Kelas XII

### Proyek: Aplikasi Absensi Siswa dengan CI/CD

Peserta didik membuat aplikasi absensi berbasis web dan menerapkan proses pengembangan serta pengelolaan aplikasi secara terstruktur.

**Tahapan proyek:**

1. Merancang kebutuhan dan fitur aplikasi.
2. Membuat aplikasi menggunakan PHP, JavaScript, atau teknologi lain yang dikuasai.
3. Mengelola kode menggunakan Git dan GitHub.
4. Membuat pipeline CI/CD menggunakan GitHub Actions.
5. Menjalankan pemeriksaan kode atau pengujian otomatis.
6. Menerapkan aplikasi ke server atau layanan hosting.
7. Menyiapkan prosedur rollback jika pembaruan gagal.
8. Menerapkan monitoring untuk memeriksa kondisi aplikasi.
9. Mengelola log untuk membantu menemukan penyebab kesalahan.
10. Memeriksa keamanan aplikasi dan mengatur hak akses.
11. Menulis dokumentasi proyek.
12. Mempresentasikan hasil proyek kepada guru dan teman sekelas.

**Hasil akhir yang diharapkan:**

Peserta didik memiliki aplikasi yang dapat dijalankan, pipeline CI/CD yang berfungsi, prosedur deployment, dokumentasi, serta bukti pengujian dan pemeriksaan keamanan sesuai ruang lingkup proyek.

## 10. Kesimpulan

CI/CD membantu mengotomatisasi proses pengembangan dan pengiriman aplikasi. Deployment terkontrol membantu mengurangi risiko saat aplikasi diperbarui. Monitoring dan logging membantu memantau kondisi aplikasi serta menemukan penyebab masalah. DevSecOps memastikan bahwa keamanan diperhatikan selama proses pengembangan dan pengoperasian.

Selain kemampuan teknis, peserta didik juga perlu memiliki kemampuan bekerja sama, menulis dokumentasi, menyelesaikan masalah, dan mempresentasikan hasil pekerjaan.

Dengan mempelajari materi ini, peserta didik diharapkan lebih siap menghadapi praktik pengembangan perangkat lunak di dunia kerja, khususnya pada bidang Software Development, DevOps, pengujian perangkat lunak, dan keamanan aplikasi.
